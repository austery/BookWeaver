# BookWeaver contributor notes

## Current product boundary

- Canonical command: `uv run bookweaver`, entry point `ai/cli.py`.
- Application composition: `ai/orchestration.py`; `translate_epub` is the only translation function.
- Supported format: EPUB-to-EPUB, alternating bilingual text (ADR-0003). The CLI and the local API reject any other input, including Markdown and PDF, with one EPUB-only error; `translate_epub` itself does not check the file name. Table cells and conservatively recognized dedicated bibliography documents remain source-only.
- Active EPUB batch default: 60,000 characters and 200 segments; CLI `--max-batch-segments` overrides `epub_resilience.max_batch_segments`. The generic batcher keeps an optional unbounded default.
- Active EPUB segmenter: `epub-leaf-block-v4-source-only-bibliography`; v3 checkpoint reuse is a hard mismatch. Segment-cap changes alone are soft mismatches; historical missing caps mean unbounded.
- Default runtime: Antigravity through `ai/adapters/providers/antigravity_provider.py`, a runtime spec on the shared adapter `ai/adapters/providers/subscription_cli_provider.py`; model versions are centralized in `ai/model_profiles.py`. Runtime adapters depend only on `ai/ports` (`ResolvedModel` is in `ai/ports/model.py`); `ai/runtime_factory.py` passes the seed list to Antigravity. `tach.toml` is exact: an unused declared dependency fails.
- Term extraction: `auto` reads the book index and stops before any model call when no usable index exists. Deep Scan (the whole book) runs only with `--glossary-mode deep-scan` or `glossary_mode=deep-scan` on the upload; no live evidence exists on a subscription CLI (issue #71). Pro stays the default extraction model. Extraction asks for one translation per term and never cuts a translation; a resume reuses the saved glossary unchanged, because it feeds the prompt hash. An EPUB run with a glossary writes `term-consistency.json`. A glossary term may carry `tier` (`fixed` or `preferred`, SPEC-028 Phase 1); preferred terms render in a second prompt block with their alternatives, and a glossary without any tier must render byte-identically (`tests/unit/test_core_glossary.py`). `bookweaver terms BOOK.epub --panel NAME` runs a named Term Panel from `terminology_panels` in configuration (SPEC-028 Phase 2a): nominators and judges from different vendors, vote rules in `ai/core/term_panel.py`, runner in `ai/term_panel.py`; its only output is a cached tiered glossary beside the EPUB. `bookweaver BOOK.epub --term-panel NAME` (Phase 2b) plans the same panel in `plan_glossary`, reuses that cache or runs the panel, then translates; it refuses `--glossary`, `--extraction-model` and `--extract-glossary`, and the invocation audit names the panel in `term_panel`. Subscription presets only; Deep Scan with a panel is not supported yet. `runtimes.disabled` in configuration (SPEC-028 §3.12) switches off a runtime: its presets leave `GET /presets`, show `disabled` in `bookweaver presets`, and a run that must call one fails before any call; a cached panel glossary still resumes.
- Default selection: Flash 3.8 Low. Model and effort are separate user axes; only named presets in `ai/model_profiles.py` `_CLI_PRESETS` are enabled (SPEC-025 §3.8), and anything else fails loudly. Pro is `gemini-4-argon`, status `experiment`. `bookweaver presets` lists these CLI presets plus the metered API presets pinned in `_API_MODELS`; `--preset NAME` replaces `--model`/`--effort`/`--provider` and cannot be mixed with them (SPEC-026 Phase 1). `uv run bookweaver serve` starts the local API on `127.0.0.1:8765` (`/docs`, `GET /presets`, and `POST /runs/upload`, `POST /runs`, `GET /runs/current`, `POST /runs/current/stop`, which run the CLI as a child process, one run at a time; run record in `$XDG_STATE_HOME/bookweaver/current-run.json`; uploaded books in `~/Documents/BookWeaver/<book name>/`; an optional `term_panel` on the upload runs `--term-panel` in `<book name>/panel-<name>-<id>/<preset>/`, SPEC-028 Phase 4); it needs the optional `api` extra, which the dev group already installs (SPEC-026 §7.3).
- Codex runtime: `ai/adapters/providers/codex_provider.py`, selected only by a `codex-*` preset (SPEC-025 §3.9). All are `experiment` at low effort; the formal model choice waits for test rounds. It uses a private login, `$XDG_STATE_HOME/bookweaver/codex-home`, so the owner's Codex rules never reach a translation. Set it up once: `mkdir -p <that path>`, then `CODEX_HOME=<that path> codex login`. `gpt-6-astra` runs only when selected by name. A resume that crosses a Codex model stops without `--force-resume`; other model changes keep their warning. To compare models on one book, use separate output folders. The local API upload does this: each Codex preset gets its own `<preset>/` folder.
- Claude Code runtime: `ai/adapters/providers/claude_code_provider.py`, selected only by a `claude-*` preset (SPEC-025 §3.10); both are `experiment` at low effort and draw on the owner's coding quota. It uses the owner's own claude.ai login, with flags that keep `CLAUDE.md`, memory and skills out of the request (`docs/plans/2026-11-09-claude-code-request-capture.md`); repeat that capture after a Claude Code upgrade (nothing enforces this yet: issue 91). `claude-sonnet-5-5-low` passed a live probe on 2.1.311 (`docs/plans/2026-11-09-claude-code-compatibility-probe.md`); Opus has not run. The owner saw no API usage after the probe; the calls were too small to show in the subscription usage. The Codex resume stop and the per-preset upload folder cover Claude Code too (`TRIAL_CLI_RUNTIMES` in `ai/model_profiles.py`): a resume that crosses a Claude Code model stops before term extraction, without `--force-resume`.
- Antigravity version gate: `CERTIFIED_AGY_MODELS` seeds `(agy version, model)` pairs with probe evidence. Any other pair runs a synthetic three-passage probe per framing protocol before its first book batch; passes are recorded in `$XDG_STATE_HOME/bookweaver/runtime-certifications.json` (default `~/.local/state/bookweaver/`). To re-probe, delete the matching entry.
- Paid API construction is authorization-gated by `ai/runtime_factory.py`. Metered providers (`gemini`, `anthropic`, `openai`) share one any-llm adapter there (SPEC-024); pinned models live in `ai/model_profiles.py`. No automatic paid fallback. No live API tests without separate authorization.
- Runtime JSON validation: `ai/runtime_config.py`, `ai/config_schema.json`. Never automatically overwrite ignored user configuration.
- Checkpoint: `ai/checkpoint_store.py`, single atomic schema-v2 document, exclusive run lock, explicit mismatch failures, legacy import without rewriting v1 files.

## Verification

```bash
uv run ruff check .
uv run ruff format --check .
uv run pytest -q
uv run tach check
uv run python scripts/check_doc_links.py
```

Test behavior through the application, provider, and checkpoint boundaries. Record live probes separately from mocked tests. A tiny EPUB or a passing registry test is not proof of whole-book translation quality. Real-book regression checks use real books, never synthetic ones: one humanities book and one technical book from the owner's library, chosen per change (owner, 2026-11-10). Do not commit book content or depend on one fixed book path; record the books used in the PR. See `docs/architecture/specs/SPEC-021-runtime-convergence-and-book-validation.md` and `docs/plans/2026-09-07-antigravity-protocol-probe.md`.

Current book evidence: `docs/plans/2026-09-07-stoic-joy-book-validation.md` and `docs/plans/2026-09-07-book-quality-polish.md`. Preserve original checkpoints when rebuilding editorial revisions; record reused, retranslated, and manually edited provenance separately.
